# Use cases

Use the pattern that matches the document. The patterns guide editing; they do not authorize structural changes.

## Skills and context files

Keep headings, links, lists, tables, and navigation order. Make the owner, first entry point, dependency, and scope clear. Label current behavior, intended behavior, and uncertainty separately.

## Procedures and runbooks

Put the condition before the command. Give one action per sentence. Keep commands exact. Put the warning after the action or command so the reader knows what to do and why the warning matters.

## Error messages

Separate three questions: what happened, what caused it if known, and what the reader should do next. Do not invent a cause from an error string alone.

## Reports and release notes

State the time or version, the observed fact, the impact, and the remaining uncertainty. Distinguish shipped behavior from planned work.

## Out of scope

Do not use this skill to rewrite code, redesign repository structure, write marketing copy, or impose a prose-only style on normal replies.
