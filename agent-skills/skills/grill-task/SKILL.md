# Define a short task plan

Use the surrounding request as context; do not ask the user to restate it.

When working in a repository, read all applicable guidance (`AGENTS.md`,
`READ.md`, and equivalents), then inspect only the documentation and code
needed to define the task. Do not make changes.

Communicate a concise plan containing:

- the desired outcome and completion criteria;
- the scope and immediate next steps;
- only the assumptions, risks, or missing context that could affect execution.

Briefly challenge the premise when useful, but keep the focus on making the
task small, clear, and executable. Ask only questions that block the plan.

If the request is sufficiently specified, state the assumptions and stop after
the plan. Keep the plan in the conversation; do not update durable project
documentation or execute the task during this skill.
