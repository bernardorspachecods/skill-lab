# Working

## Research brief and boundaries

- **Question:** map terminology and mechanisms for feedback loops in direct user–AI workflows for information work (researching, planning, drafting, analyzing, coding, and tool use), distinguishing user-facing workflow evidence from adjacent agent-internal/model-training meanings.
- **Consumer:** LR-06 S1 synthesis, then independent review and coordinator reconciliation. This is evidence mapping, not application advice or a claim of exhaustiveness.
- **Rigor:** Standard academic research. Sources are primary empirical studies or documented systems where possible; search results and abstracts were leads, not evidence.
- **Date:** 2026-10-07 (Europe/Lisbon). Access dates below refer to this collection pass.
- **Explicit exclusion:** LR-05 artifacts were not searched or used as evidence inputs. Model-training feedback literature was not researched in this S1 pass; it is a different object from a user’s work loop.

## Working claim map

- **C1 / terminology:** “workflow,” “collaboration,” “prompt iteration,” “monitor/evaluate,” “confirmation,” “information foraging/sensemaking,” and “action–observation” can describe different levels of feedback. Need direct primary evidence and an explicit boundary between user-facing and internal loops.
- **C2 / generic mechanism:** user states/refines intent → AI responds or acts → user inspects against need/evidence → user accepts, revises, redirects, verifies, or stops. Need studies in more than one task type.
- **C3 / multistep-agent recovery:** user checkpoint/confirmation → error detection → diagnosis → correction → redo; inspect whether efficacy was compared and whether settings were simulated.
- **C4 / feedback signal and verification:** map the actual signal and check method by task; do not assume that another prompt is the only feedback.
- **C5 / neighboring meaning:** distinguish action/environment feedback and self-reflection cycles from human-supervised workflow; do not claim detailed mechanisms without inspecting the originating technical papers.
- **C6 / evidence limits:** separate descriptive associations, qualitative observations, user preference, simulated comparison, and causal effects; search for adverse findings/limits.

## Academic orientation / findings

These F-cards orient the findings; audit E# entries are the canonical exact claim support.

### F1 — Coding-agent collaboration

- **Objective/design:** observe developers using an in-IDE agent for open coding issues; 19 professional participants; one-company sample; 269 prompts across 33 issues.
- **Reported finding:** one-shot and incremental-resolution patterns; incremental issue strategy and expert insights associated with greater issue success in the small descriptive dataset; agents sometimes agree with latest corrections rather than reason substantively.
- **Limit:** exploratory, descriptive, non-causal; one company, early Cursor exposure, study observation and forced AI-use instruction. See E1/E7.
- **Our synthesis:** strong case for task decomposition, user context, iteration, and side-effect review; does not establish a universal “always do incremental” rule.

### F2 — Interactive deep research

- **Objective/design:** build an interactive deep-research interface, formative study and 15-user study with frequent deep-research users.
- **Reported finding:** users value visibility of process/dependencies and timely control; graph view rated positively; cross-view interaction preferences differed.
- **Limit:** preprint, small experienced sample, trained use, mostly questionnaire/interview; no objective answer-quality comparison. See E2.
- **Our synthesis:** research loops can be steered and audited by tracing result-to-source lineage; this remains an interface/mechanism case, not proven accuracy improvement.

### F3 — Data-analysis workflow

- **Objective/design:** N=15 participatory prompting sessions using Bing Chat to explore self-selected spreadsheet/data-sensemaking tasks; researcher mediates prompt entry.
- **Reported finding:** AI assists information foraging and hypothesis/sensemaking loops, while user effort remains around intent/context formulation and verifying outputs.
- **Limit:** mediation, artificial study session, and self-selected tasks alter ecological validity. See E3.
- **Our synthesis:** process feedback may update either the query/context or the analytic hypothesis/plan; external-source and result checks are distinct from prompt revision.

### F4 — Conversational information-seeking iteration

- **Objective/design:** N=15 think-aloud study with custom ChatGPT-4o interface and fictional health scenarios.
- **Reported finding:** query revision, evaluation, workflow adaptation; users sometimes rephrase through near-synonyms to assess whether the agent understood them; repeated rephrasing can be unproductive if the model remains anchored.
- **Limit:** simulated health information use and qualitative sample; not general clinical efficacy. See E4.
- **Our synthesis:** a user can feed back by modifying language, but may need a system explanation or a changed approach rather than another same-form rephrase.

### F5 — Checkpointed multistep tasks

- **Objective/design:** formative study (n=8) and within-subject controlled evaluation (n=48) of confirmation scheduling across shopping, image editing, and game tasks.
- **Reported finding:** CDCR pattern; model-scheduled intermediate checkpoints preferred by 81% and reduced completion time 13.54% vs end-only baseline in the simulated setup.
- **Limit:** simulated environment with fixed accuracy/execution time; study domains do not include ordinary knowledge work; no current deployed equivalent. See E5.
- **Our synthesis:** correction after a late failure may entail diagnosing where the sequence first diverged and redoing dependencies; optimal check cadence must depend on user and task costs, not inferred universally from this result.

### F6 — Code suggestion interaction

- **Objective/design:** qualitative study of 20 programmers using Copilot on designed coding tasks.
- **Reported finding:** known next steps invite fast triage; unfamiliar tasks invite explicit prompts, multiple suggestions, and careful checks by inspection, execution, static analysis, or documentation.
- **Limit:** non-agent code completion, short sessions, study tasks rather than ongoing project work, sample skew. See E6.
- **Our synthesis:** task uncertainty changes how the human evaluates feedback; do not transfer this directly to tool-using agent execution.

## Marginal / negative findings retained during collection

- **Midjourney prompt iteration (Q1):** observational image-generation logs establish prompt changes after model outputs, but not an information-work process or agent action workflow. The authors use upscaling as a satisfaction proxy and acknowledge it is imperfect; it was not used for a core claim.
- **Prewriting co-creativity (Q4):** iterative creative-writing phases surfaced as a possible drafting taxonomy, but creative ideation is not the core information-work boundary; not used for core claims.
- **System-internal loops (Q5):** relevant agent architectures surfaced, but the primary technical papers were not inspected after a tool failure. No claim that a specific internal loop “works” is made.
- **Study-specific failure cases:** one code agent’s terminal action deleted a log file/corrupted environment (S1); Copilot-generated code could be harder to debug (S6); health users could fall into unproductive rewording (S4); InterDeepResearch users differed in interface preferences (S2). These constrain overly positive or uniform loop stories.

## Collection coverage and stopping rationale

- **Covered routes:** broad user/agent interaction terminology; coding-completion studies; in-IDE autonomous SWE-agent collaboration; research/deep-research interaction; conversational information seeking; data analysis/sensemaking; multistep confirmation and error recovery; writing task-role evidence; adjacent creative-writing and internal-agent terminology.
- **Primary-source coverage achieved:** distinct direct primary studies for coding agents, deep research, data-analysis workflows, conversational information seeking, multi-step tool-use checkpoints, coding assistance, and a writing task-allocation experiment (repository abstract only). Coverage spans qualitative/descriptive studies and one controlled checkpoint comparison; the writing study reports a quasi-experimental outcome in its abstract.
- **Why collection stopped:** across these task types, source terminology converged on a workable first-pass distinction among (a) user turns that update intent/feedback, (b) domain work-process loops, (c) checkpoint/repair loops for multi-step actions, and (d) agent-internal environment-feedback cycles. Another source likely adds an instance but is less likely to alter these categories; sources also reveal non-uniform findings and distinct measured outcomes. Stop is for this bounded S1 terminology/map deliverable only.
- **Routes not exhausted:** citation chaining was selective; browser/office-agent deployments and dedicated planning studies remain thinner than coding/research; the writing study was available only as a repository abstract; ReAct/Reflexion full-text extraction was not completed. No open-web recall estimate or exhaustive taxonomy is claimed.
- **Candidate term evolution:** began with “feedback,” “iteration,” “workflow,” and “user–agent”; added “prompt iteration,” “incremental resolution,” “steering,” “context backtrace,” “information foraging,” “sensemaking,” “CDCR,” and “acceleration/exploration” when primary sources yielded these exact labels. Kept the generic term “human-in-the-loop” underspecified rather than using it to collapse distinct actions.
