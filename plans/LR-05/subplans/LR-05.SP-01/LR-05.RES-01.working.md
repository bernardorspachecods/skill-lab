# Working

## Brief and working boundary

- **Question:** What range of feedback/revision loop mechanisms and terminology is used in AI information work, and how do sources distinguish them?
- **Consumer:** LR-05.SP-01 and downstream SP-02/SP-03; this is a vocabulary and mechanism map, not a recommendation.
- **Boundary:** Search from “automated loops”; include direct AI/information links across technical, human, organizational contexts. Keep general control/iteration systems as adjacent unless a source ties them to AI information work. No exhaustive-recall claim.
- **Date of searches/access:** 2026-09-30. No date cutoff was imposed because the question concerns current terminology and mechanisms with older foundational terms.
- **Discovery approach:** Collection-first web searching; inspect papers, authoritative frameworks, and implementation documentation. Search hits/snippets were leads only.

## Search record

### Q1 — User phrase and broad feedback-cycle vocabulary

- **Date/surface:** 2026-09-30; web search.
- **Exact queries:** `"automated loops" AI information work feedback loop`; `AI feedback loop taxonomy human in the loop machine learning closed loop review`; `LLM self-refinement iterative feedback evaluator optimizer paper`; `AI agent action observation loop feedback control information retrieval`.
- **Purpose:** Baseline terminology and find distinct technical, human, and agent-cycle interpretations.
- **Candidate sources inspected:** Madaan et al., *Self-Refine* (arXiv:2303.17651), abstract/introduction; Ouyang et al., *Training language models to follow instructions with human feedback* (arXiv:2203.02155), abstract/method; Springer review *Human-in-the-loop machine learning: a state of the art*, introduction; Google Cloud agentic AI patterns, ReAct and HITL sections; Pan et al., *Spontaneous Reward Hacking in Iterative Self-Refinement* (arXiv:2407.04549), abstract/introduction; ACL 2024 *Iterative Self-Refinement in LLMs*, §3.1. Additional discovery leads included Hugging Face agent course, AWS agent documentation, and a recent HITL systematic review; these were not needed for core evidence after primary/review sources supplied the distinctions.
- **Terms added:** `self-refinement`, `self-feedback`, `RLHF`, `agent thought-action-observation`, `human-in-the-loop`, `interactive machine learning`, `active learning`, `machine teaching`, `evaluator-optimizer`, `reward hacking`.
- **Marginal result:** “Loop” is not a unified class. Search found at least inference-time revision, parameter/data learning, environment action-observation, and human-supervised interaction. Baseline phrase itself produced noisy commercial results, so subsequent paths use field terms.

### Q2 — Human feedback and human role vocabulary

- **Date/surface:** 2026-09-30; web search, Springer Nature article, AAAI Symposium proceedings, NIST AI RMF.
- **Exact queries:** `site:arxiv.org human feedback loop machine learning active learning interactive machine learning taxonomy human in the loop`; `human over the loop in the loop on the loop terminology AI oversight taxonomy research`.
- **Purpose:** Establish source-described distinctions between human annotation, interaction, oversight, and organizational feedback; check whether preposition terms are consistent.
- **Candidates inspected:** Springer Nature review, §§1–4 and terminology discussion; Singh & Szajnfarber, “Preposition Salad…” AAAI Symposium Series (2025), abstract and bibliographic record; NIST AI RMF Core, Govern/Map/Measure/Manage; Ouyang et al. (2022), methods; AWS Well-Architected ML Lens human-in-the-loop monitoring page.
- **Terms added/revised:** `human-in-the-loop ML`, `human oversight`, `human-AI configurations`, `AI actor feedback`, `adjudicated feedback`, `human-on/over/under/along-the-loop`. The latter terms are retained as evidence that oversight vocabulary is unsettled, not adopted as a stable universal taxonomy.
- **Marginal result:** Springer review differentiates active learning (system selects examples and humans label), interactive ML (more frequent/incremental user interaction), and machine teaching (expert directs what knowledge to transfer). NIST describes lifecycle/organizational risk activities rather than an execution loop. AAAI explicitly reports inconsistent uses of HITL/team terms.

### Q3 — Retrieval and recommendation feedback

- **Date/surface:** 2026-09-30; web search, Stanford IR textbook PDF, ACM result page, primary research papers on arXiv.
- **Exact queries:** `relevance feedback information retrieval user modifies query document rankings original paper Rocchio relevance feedback`; `algorithmic feedback loops recommender systems user behavior recommendations feedback loop AI`; `recommendation feedback loop machine learning information exposure user behavior perpetuating data paper`.
- **Purpose:** Test information-seeking and personalization as cases where feedback changes information retrieval or later training data, rather than only generated text.
- **Candidates inspected:** Manning, Raghavan & Schütze, *Introduction to Information Retrieval*, ch. 9, especially pp. 178–187; Krauth, Wang & Jordan, *Breaking Feedback Loops in Recommender Systems with Causal Inference* (2022), abstract/introduction; Mansoury et al., *Deconvolving Feedback Loops in Recommender Systems* (2017), abstract/introduction; ACM TOIS *A Re-classification of Information Seeking Tasks and Their Computational Solutions* (2022) result page; search surfaced further simulation work (Mansoury et al., *Feedback Loop and Bias Amplification…*, 2020), not separately inspected in depth.
- **Terms added:** `relevance feedback`, `explicit/implicit feedback`, `pseudo/blind relevance feedback`, `query expansion`, `recommendation-user response-retraining loop`, `algorithmic confounding`, `exposure feedback`.
- **Marginal result:** Retrieval uses relevance judgments/clicks to adjust query or ranking; recommender loops are endogenous: recommendations shape behavior/observed data, which changes later recommendations. These differ from deliberate revision of one output. The IR source distinguishes explicit, implicit, and pseudo feedback and documents drift/user burden limits.

### Q4 — Production monitoring and organization-level AI governance

- **Date/surface:** 2026-09-30; NIST AI RMF Core, NIST deployed-monitoring report announcement, AWS Well-Architected ML Lens.
- **Exact queries:** `NIST AI RMF monitor feedback ongoing monitoring AI systems govern human oversight feedback lifecycle official`; `AI system life cycle monitoring feedback governance human oversight NIST AI RMF`.
- **Purpose:** Capture organizational/operational loops that observe deployed systems and route information to changes, risk response, or governance decisions.
- **Candidates inspected:** NIST AI RMF Core, §§5.1–5.4, especially Govern 1.5/5.1–5.2, Measure 3–4, Manage 4; NIST news entry for AI 800-4, monitoring categories and identified open questions; AWS ML Lens `Monitoring` and `Include human-in-the-loop monitoring`; AWS automated retraining guidance.
- **Terms added:** `post-deployment monitoring`, `drift detection`, `alert-to-action`, `retraining trigger`, `risk monitoring`, `incident/appeal/override`, `continual improvement`.
- **Marginal result:** Operational monitoring is often event/schedule/threshold-driven and may change model/data/deployment, but governance frameworks also include organizational review, appeals, impacted-party input, and shutdown. Those practices are lifecycle control and oversight cycles, not necessarily automatic model learning. NIST 2026 identifies fragmentation and gaps in human-AI feedback loop research.

### Q5 — Evaluator/generator revision terminology and refutation pass

- **Date/surface:** 2026-09-30; Microsoft Learn agent patterns and empirical papers.
- **Exact query:** `LLM iterative refinement evaluator optimizer pattern official documentation agent feedback loop evaluator-optimizer`.
- **Purpose:** Verify whether “evaluator-optimizer” is product/pattern vocabulary and compare it with empirical self-refinement work and failure evidence.
- **Candidates inspected:** Microsoft Learn, “Agentic Application Patterns,” Evaluator-optimizer subsection; Madaan et al. (2023), *Self-Refine* abstract/introduction; Pan et al. (2024), *Spontaneous Reward Hacking…* abstract/§1–2; ACL 2024 *Iterative Self-Refinement in LLMs* §3.1.
- **Terms added:** `generator-evaluator`, `critique-revision`, `bounded refinement`, `fixed iteration/exit condition`, `self-bias`, `in-context reward hacking`.
- **Marginal result:** Vendor docs specify an engineering pattern (generator, evaluator, criteria, repeat/exit), while research labels vary (`self-refinement`, `iterative self-refinement`). Evidence qualifies any assumption that repeated evaluator gains imply real-world quality gains: evaluator-human divergence/reward hacking and self-bias are studied failure modes.

## Candidate source pool and dispositions

- **Retained core:** S1–S13 in audit. Sources cover original empirical/method papers, field review, textbook treatment, public frameworks, and implementation guidance. AWS/Microsoft are used only for documented operational/pattern descriptions, not comparative effectiveness.
- **Lead-only / excluded:** Wikipedia, Reddit, marketing/news copy, generic “automated loops” vendor language, and low-accountability agent pattern blogs were not used as evidence. They were too weak or derivative for definitions. The search surfaced an apparently recent HITL review in PMC and other 2026 reviews, but it was not relied on: the established Springer survey plus primary and standards sources provided inspected terminology, and an open-access mirror triggered a retrieval challenge. This is a bounded choice, not a quality finding about the entire work.
- **Sentinel check:** No established sentinel source was supplied by the plan or repository. Searches did retrieve expected seed items (Self-Refine, RLHF/InstructGPT, relevance feedback, agent loop, NIST monitoring), so retrieval of known leads was checked, not web recall.

## Search coverage / stopping notes

The initial search passes crossed the baseline phrase, adjacent ML/HCI labels, output refinement, retrieval, recommender systems, agent/environment cycles, and lifecycle monitoring/governance. The new terminology from each pass opened at least one materially distinct mechanism class. The later six-area coverage probe and final stopping rationale are recorded below; this initial note is retained as the reason the first evidence draft was prepared for review, not as the final coverage boundary. SP-02 may add application domains and outcomes; do not interpret any stop here as exhaustive coverage.

## Navigation/provenance notes

- The browser result for the 2026 HITL systematic review (PMC) was blocked by a reCAPTCHA when opened; search result metadata/summary was not promoted to evidence.
- Google Cloud pattern text is vendor architecture guidance, directly useful for its named ReAct/HITL descriptions but not efficacy claims.
- NIST AI RMF is voluntary guidance; it documents processes and expected outcomes, not evidence that a loop improves model quality.
- Stanford *Introduction to Information Retrieval* is a textbook, used for canonical terminology and mechanics rather than a claim about contemporary AI-specific deployment prevalence.

## Bounded coverage probe added for formal review

All searches and inspections below were conducted 2026-09-30. This tests six specified coverage gaps; it is not a domain inventory. Search-result snippets were candidate leads; only inspected source text informs classification.

### Q6 — Robotics/control

- **Exact query:** robotics AI closed-loop control perception action feedback loop survey autonomous robot learning information feedback primary source
- **Purpose:** Distinguish embodied AI learning/control from general agent and information feedback terminology.
- **Surface and inspected path:** Web search; opened Taylor, Berrueta & Murphey, *Active Learning in Robotics: A Review of Control Principles*, arXiv:2106.13697, abstract and bibliographic record ([source](https://arxiv.org/abs/2106.13697)). Search also surfaced *Safe Learning in Robotics* (Annual Reviews) and a robotics deliberation survey; neither was opened.
- **Finding/classification:** Review describes embodied active learning as analysis plus action, continuous online learning, with information content of observations, action plans, control objectives, safety, and environment/robot uncertainty. **Adjacent/closely related**, not a new core family: it overlaps agent action-observation and adaptive learning, but primarily controls a physical robot/environment. Its broad cycle shape transfers; embodied control details do not.
- **Rejected expansion:** Do not expand to all control theory. Retain embodied active learning/active perception/safe learning-control as adjacent vocabulary.

### Q7 — Scientific workflows/discovery

- **Exact query:** AI closed-loop scientific discovery workflow autonomous laboratory active learning Bayesian optimization paper
- **Purpose:** Test where AI selects scientific observations/experiments and assimilates results.
- **Surface and inspected path:** Web search; opened Kusne et al., *On-the-fly Closed-loop Autonomous Materials Discovery via Bayesian Active Learning*, arXiv:2006.06141, abstract and bibliographic record ([source](https://arxiv.org/abs/2006.06141)). Nature Communications result page surfaced but did not open in the available browser.
- **Finding/classification:** Authors describe a closed-loop active-learning materials system (CAMEO) at a synchrotron beamline, with autonomous hypothesis definition/evaluation and seconds-to-minutes cycles for mapping/optimization; report a material discovery. **Instance of active learning plus tool/environment action-observation**, not a new general mechanism. The abstract does not detail human scientific supervision.
- **Rejected expansion:** Do not treat one reported discovery as proof that autonomous science loops generally work.

### Q8 — Labeling operations

- **Exact queries:** human-in-the-loop data labeling operations active learning annotation workflow primary study machine learning; earlier Q2 query: site:arxiv.org human feedback loop machine learning active learning interactive machine learning taxonomy human in the loop
- **Purpose:** Determine whether annotation is distinct from HITL/active learning.
- **Surface and inspected path:** Web search; inspected NIST TN 2287, *Human-in-the-loop Technical Document Annotation*, May 2024, PDF pp.17–23 / lines 677–717, 741–765, 786–823 ([source](https://nvlpubs.nist.gov/nistpubs/TechnicalNotes/NIST.TN.2287.pdf)). Search candidates included 2026 VILOD and HILTS papers, not opened.
- **Finding/classification:** NIST describes classifier-selected document → human label → classifier training/update → repeat, with topic models supporting corpus-level structure. It reports a 60-user study and notes semantic label quality can lack a single right answer. **Instance of existing HITL/active-learning family** specialized to document annotation; no new family needed. Adds human authority over ambiguous label categories.
- **Rejected expansion:** Candidate product/abstract-only annotation sources were not used; the NIST technical note provided an inspectable public study.

### Q9 — Online/adaptive experiments

- **Exact queries:** online adaptive experimentation contextual bandit feedback loop machine learning experiment primary paper; adaptive experimentation contextual bandits online experiments multiarmed bandit primary study user interaction feedback evaluate exploration
- **Purpose:** Test sequential experiments where outcomes adjust later assignments and optimization coexists with statistical inference.
- **Surface and inspected path:** Web search; inspected *Using Adaptive Bandit Experiments to Increase and Investigate Engagement in Mental Health*, open-access article, lines 219–237 and 312–380 ([source](https://pmc.ncbi.nlm.nih.gov/articles/PMC11044947/)). Search candidates included an online-advertising bandit paper and a bandit experiment-design survey; neither was opened.
- **Finding/classification:** Contextual bandits adapt intervention/message assignments from context and observed ratings/clicks, aiming at cumulative reward/personalization while retaining data for statistical inference; authors compare with uniform random assignment in deployment/simulation. **Distinct named family/subtype worth adding: adaptive experimentation/contextual-bandit allocation.** It shares online learning structure with recommenders but has an explicit dual objective: allocate experiment arms and acquire interpretable evidence. This distinction is this audit's synthesis, not a universal taxonomy.
- **Rejected expansion:** Ordinary A/B tests without AI-adaptive allocation are outside the loop map.

### Q10 — AIOps

- **Exact queries:** AIOps closed loop automation event detection diagnosis remediation feedback loop system official NIST research; closed loop AIOps feedback loop incident management AI operations primary study; AIOps survey artificial intelligence for IT operations incident detection root cause analysis automation feedback loop academic survey; AI operations AIOps closed-loop automation framework official documentation monitor remediate verify incident
- **Purpose:** Distinguish AI processing of incident information from a genuinely recurring feedback mechanism.
- **Surface and inspected path:** Web search; inspected Microsoft Research record for Chen et al., “Towards intelligent incident management: why we need it and how we make it,” FSE 2020 page, abstract/bibliographic record ([source](https://www.microsoft.com/en-us/research/publication/towards-intelligent-incident-management-why-we-need-it-and-how-we-make-it/)). ACM Computing Surveys “A Survey of AIOps in the Era of Large Language Models” could not be opened (403). Trade press, Wikipedia, and preprint proposals were not used.
- **Finding/classification:** The empirical Microsoft study describes AIOps as helping understand incidents/provide recommendations; it covers over two years of incident management and presents IcM BRAIN, noting incomplete dependencies and imprecise health assessment. The inspected abstract does not establish a recurring feedback/action/retraining loop. **Adjacent operational domain with a direct AI/information connection but not a loop evidenced by this source.** It fits monitoring/agent families only when a specific case closes an alert-to-action/verification cycle.
- **Rejected expansion:** Generic “self-driving IT” claims were not promoted without accountable inspected evidence detailing the cycle.

### Q11 — AI software engineering

- **Exact queries:** LLM self-debug code iterative feedback compiler tests error messages paper primary research; AI software engineering agent feedback loop test execution observation revise code ReAct compiler feedback paper
- **Purpose:** Test whether code generation/debugging is new or an instance of refinement/agent cycles with an external correctness signal.
- **Surface and inspected path:** Web search; inspected Chen et al., *Teaching Large Language Models to Self-Debug*, arXiv:2304.05128, abstract and §§1–2 / lines 3–6, 16–24, 54–57, 199–203 ([source](https://arxiv.org/abs/2304.05128)). Search surfaced newer code-correction work, an ACM programming-languages article, and LLMLoop; none inspected.
- **Finding/classification:** Self-Debugging executes code, forms feedback from execution results and model explanation, then feeds it to the model for debugging; unit tests supply signals where available, otherwise the model can use code explanation. The paper evaluates SQL, code translation and Python benchmarks. **Instance of existing output-refinement and agent action-observation families**, with an external/tool feedback subtype (compiler, interpreter, tests, static analysis). Tests are only as complete as their coverage.
- **Rejected expansion:** One-shot code generation and all AI-assisted software development are not loop cases; require recurrent diagnostic/observation-to-revision paths.

### Cross-probe scope result

- Four areas map to existing families: scientific active learning, document-labeling/HITL, code self-debugging, and AIOps when a specific cycle is present. Adaptive experimentation adds a useful named subtype with a distinct allocation/inference objective. Robotics remains adjacent embodied active learning/control.
- The probe surfaced a useful false positive: a domain can use AI on operational information without the inspected source documenting recurrence/feedback. Classify mechanisms, not industries merely because they use AI.
- Six bounded paths added useful coverage. Further searching risks becoming domain inventory; stop this probe here. S1 remains non-exhaustive.
